# Security policy

Report a vulnerability in keel privately, by email to `security@<owner to fill>`. Never report one
in an issue, a pull request or a discussion: this repository is public, and so is everything
posted to it.

## What a report should hold

- The version of keel affected (the contents of `VERSION`, or the commit).
- The steps that show the problem, in the order you took them.
- The impact, as you see it.

## Audits of keel itself

Security audits of keel are kept in a private repository until their findings are fixed, so a fix
can ship before its description does.

## No CLA

There is no contributor licence agreement. Contributions carry a `Signed-off-by:` line under the
Developer Certificate of Origin, as `CONTRIBUTING.md` says.
