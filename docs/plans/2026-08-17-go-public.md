> **For agentic workers:** use `keel:execute-plan` to implement this task by task.
> Steps use `- [ ]` checkboxes; tick them as you go, on output you read.
> A box for a step you did not perform yourself is ticked only with a note naming what you did

> **REQUIRED SUB-SKILL:** `keel:tdd` for every task.

**Goal:** execute `docs/runbooks/going-public.md` up to but not including the irreversible step, then
publish a plugin subset as a fresh public repository under an MIT licence.

**Scope comes from** `docs/runbooks/going-public.md` and three decisions taken 2026-08-17:

1. **Vehicle:** a fresh public repository with one initial commit and no history. This repository
   stays private as the development history.
2. **Licence:** MIT.
3. **Path:** this repository is renamed `gbi-solutions-ltd/keel-internal`; the public one takes
   `gbi-solutions-ltd/keel`. **Consequence: every committed URL is already correct** and step 4 of
   the runbook reduces to one paragraph of prose.

**ADRs:** none new. ADR-0001 bounds any skill body this touches; task 3 only removes words.
**Architecture:** one real change, the deny list moving out of the tree behind an environment
variable with a generic fallback. Everything else is prose, a file rename, and an export.

- **Nothing in tasks 1 to 5 and 7 changes repository visibility.** Only task 6 does, and it is gated
  on an explicit go-ahead recorded in this file.

## The manifest, and where it departs from the decision

The decision said "ship the plugin and leave `docs/` and `IMPLEMENTATION-PLAN.md` behind". **Executing
that literally fails, and the failure is one this repository just created.** PR 24 added a validator
rule that checks relative links in root documents, and `README.md` links into `docs/` fourteen times,
so a subset without `docs/` fails `tests/validate-skills.sh`, its own gate, on the first run.

Measured rather than assumed. Two further facts move the line:

| Finding | Evidence |
|---|---|
| `HEAD` carries no client identifier at all, outside the deny list and its test | `git ls-files` swept against all 27 patterns: only `tests/no-internal-leaks.sh` and `tests/test-no-leaks.sh` match |
| Exactly one file under `docs/` names a GBi service | `docs/audits/2026-08-15-existing-service-pilot.md`, `agroplex` and `agroplex-express-api`. No other file under `docs/` names one |
| `IMPLEMENTATION-PLAN.md` names both pilot repositories | `GBi/forex-market-place` and `GBi/Express/agroplex-express-api`, in task 7.1 |
| Excluding those two breaks exactly two links | `CHANGELOG.md` to the audit, and `README.md` to the plan |

So the exclusion that serves the decision's **reason**, which was exposure, is narrower than the
decision's letter:

**Excluded:** `docs/audits/` (five files, 838 lines, the security posture of GBi's own services),
`IMPLEMENTATION-PLAN.md` (an internal build plan naming both pilot repositories, and of no use to a
consumer), `.keel/handoff.md` (already gitignored), `.claude/` (this repository's own settings).

**Included:** everything else, which keeps `docs/01` to `docs/07`, `docs/standards.md`,
`docs/decisions/`, `docs/ideas/`, `docs/plans/` and `docs/runbooks/`. Those are the reasoning that
makes the repository worth reading, they are the cost the chosen option was told it would pay, and
the sweep says they are clean.

**This is a departure and it is the user's to veto.** It publishes more than "the plugin". Task 5
stops and asks before task 6 runs.

### Task 2: Move the deny list outside the tree

**Kind:** `build`. This is the only behaviour change in the plan and it is the disclosure guard.
**Files:** Modify `tests/no-internal-leaks.sh`, `tests/test-no-leaks.sh`, `CONTRIBUTING.md`.

**Interfaces:**
- Produces: `KEEL_DENY_FILE`, an environment variable naming a file of extra patterns, one per line,
  `#` comments and blanks ignored. Default
  `${XDG_CONFIG_HOME:-$HOME/.config}/keel/internal-deny-list.txt`.
- Produces: a mode line on every run, before any finding.
- Consumes: `--list-patterns`, which must keep printing exactly the loaded set, because
  `tests/test-no-leaks.sh`'s coverage assertion reads it.

**Done when:** `tests/test-no-leaks.sh` passes with its new cases, `tests/no-internal-leaks.sh`
against this repository prints a mode line and `OK`, and `tests/run-tests.sh` reports
`All test files passed`.

**The design, and the guarantee it gives up.** Today `tests/test-no-leaks.sh` contains every client
name, because its coverage assertion feeds one sample file through the scanner and checks that every
declared pattern fired. That file is therefore a second copy of the disclosure, and it cannot move
out while the assertion works that way.

After this task the samples are **invented names**, the coverage assertion proves the *mechanism*
rather than the real list, and the real list's coverage becomes the internal file's problem. That is
a real reduction and it is recorded in the script rather than glossed: a pattern in the internal file
that matches nothing is no longer detected by anything here.

The alternative considered and rejected for now: give the internal file a `pattern<TAB>sample` format
so coverage can be checked whenever it is present. It is the better end state and it is more
machinery than this step needs; recorded in the script so the next reader does not have to re-derive
it.

```bash
# was therefore the second copy of the disclosure, alongside the scanner itself.
```

```bash

deny_mode="generic patterns only, no internal deny list at $DENY_FILE"

        case "$line" in ''|\#*) continue ;; esac
```

- [x] **Step 2: Write the export script**

Create `tests/export-public.sh`. It copies tracked files only, so nothing untracked or ignored can
leak, and it excludes the manifest's four entries:

```bash
#!/usr/bin/env bash
# Write the public subset of this repository to a directory.
#
# The public repository is a fresh tree with one commit and no history, because this repository's
# history carries client identifiers in six files and two commit messages and cannot be published.
# See docs/runbooks/going-public.md.
#
# Tracked files only, via git ls-files, so nothing untracked, ignored or local can be carried out by
# accident. The exclusions are the exposure, not a tidy-up:
#
#   docs/audits/          the security posture of real services, named
#   IMPLEMENTATION-PLAN.md  an internal build plan naming both pilot repositories
#   .claude/              this repository's own editor settings
#   .keel/handoff.md      already gitignored, excluded belt and braces
#
# Usage: tests/export-public.sh <empty-or-absent-directory>
set -uo pipefail
cd "$(dirname "$0")/.." || exit 1

dest="${1:-}"
[ -n "$dest" ] || { printf 'usage: tests/export-public.sh <dir>\n' >&2; exit 2; }
if [ -e "$dest" ] && [ -n "$(ls -A "$dest" 2>/dev/null)" ]; then
    printf 'refusing to write into a non-empty directory: %s\n' "$dest" >&2
    exit 2
fi
mkdir -p "$dest" || exit 2

excluded() {
    case "$1" in
        docs/audits/*|IMPLEMENTATION-PLAN.md|.claude/*|.keel/handoff.md) return 0 ;;
        *) return 1 ;;
    esac
}

n=0
while IFS= read -r f; do
    excluded "$f" && continue
    mkdir -p "$dest/$(dirname "$f")"
    cp -p "$f" "$dest/$f"
    n=$((n+1))
done < <(git ls-files)

printf 'exported %s files to %s\n' "$n" "$dest"
printf 'excluded: docs/audits, IMPLEMENTATION-PLAN.md, .claude, .keel/handoff.md\n'
```
