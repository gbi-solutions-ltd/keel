# Profile keys

Every key `.keel/profile.json` may contain, what it does, whether keel writes it, and what
reads it back.

Generated by `tests/generate-profile-keys.sh` from `templates/profile.schema.json`.
Do not edit by hand: `tests/validate-skills.sh` fails when this file and the schema
disagree, and names the command that regenerates it.

**Set by** is derived by running `keel init` against a throwaway fixture, so it cannot
drift from what init actually writes. A key marked **you** is one keel never writes: it
does nothing until a human adds it.

**Read by** comes from each key's `x-keel-read-by` in the schema, and
`tests/validate-skills.sh` fails when the citation it gives no longer points at a real,
non-blank line. A file and line means something there reads the value; "(advisory)" marks
prose a model may follow rather than code that executes; "a person" means the key exists to
be read by a human or quoted into a runbook; "nothing yet" means nothing reads it and names
the record that decided so. The check proves the citation resolves, not that it matches the
key: 20 of 61 keys were read by nothing on 2026-09-07 while the changelog recorded seven.
